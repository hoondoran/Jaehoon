# 공시지가 산정 — 표준지 GIS

표본목록 엑셀의 **텍스트 소재지(G열 "표준지 위치")** 를 좌표로 바꿔 지도에 올리고,
표준지 공시지가의 **산정식을 재계산·검증**하는 단일 페이지 웹 도구입니다.

대상: **대구광역시 달성군 표준지 1,043필지** (화원읍 321 · 논공읍 364 · 옥포읍 358)

---

## 빠르게 실행

카카오 지도 SDK는 `file://` 에서 동작하지 않으므로 로컬 서버로 엽니다.
Node·Python 없이 PowerShell만으로 동작합니다.

```bash
powershell -ExecutionPolicy Bypass -File tools/serve.ps1
```

브라우저에서 <http://localhost:8080> 접속 → 좌측 상단 **📍 좌표 변환** 1회 실행 →
끝나면 **⬇ coords.js 저장** 을 눌러 받은 파일로 `data/coords.js` 를 덮어씁니다.
이후로는 지오코딩 없이 즉시 지도가 뜹니다.

---

## 좌표 확보 (텍스트 소재지 → GIS)

엑셀에는 좌표 열이 없고 지번주소와 PNU만 있습니다. 두 가지 경로를 지원합니다.

**① 카카오 지오코딩 (기본)**
`대구광역시 달성군` + G열 지번주소로 조회하고, 실패하면 도로명주소 → 본번만 순으로
재시도합니다. 결과는 브라우저 `localStorage` 에 캐시되고 `data/coords.js` 로 내보낼 수 있습니다.

> **appkey 도메인 등록이 필요합니다.**
> [카카오 개발자 콘솔](https://developers.kakao.com) → 내 애플리케이션 → 플랫폼 → Web 에
> `http://localhost:8080` 과 GitHub Pages 주소(`https://<계정>.github.io`)를 등록하세요.
>
> 등록되지 않은 도메인에서도 **SDK 스크립트 자체는 정상 로드됩니다.** 거부되는 것은
> 주소 검색(`addressSearch`) 호출이고, 이때 카카오는 "결과 없음"이 아니라 오류를 돌려줍니다.
> 그래서 겉보기에는 "변환은 도는데 전부 실패"처럼 보입니다. 이 경우를 구분하려고
> 초반 5회가 모두 거부되면 즉시 중단하고 등록해야 할 origin을 그대로 찍어 줍니다.
>
> appkey는 `index.html` 하단 스크립트 태그에서 바꿉니다.

**② 좌표 CSV 가져오기 (대체)**
카카오 키를 쓸 수 없을 때 **⬆ 좌표 CSV** 로 `PNU, 위도, 경도` 열을 가진 CSV를 넣으면 됩니다.
헤더 이름(`PNU`/`고유번호`, `위도`/`lat`/`y`, `경도`/`lng`/`x`)을 자동 인식하고,
헤더가 없으면 1·2·3열로 봅니다. 위경도가 뒤바뀐 파일도 자동 보정합니다.

## 배경지도 — 카카오맵

배경지도(일반·위성·하이브리드·**지적편집도**)는 카카오맵을 쓰고, 마커 1,000여 개의
캔버스 렌더링과 히트맵은 Leaflet이 담당합니다. `#kakao-map`(아래) 위에 투명한
`#map`(Leaflet)을 겹쳐 두고, 조작은 Leaflet이 받아 카카오 지도를 따라오게 동기화합니다
(`js/kakao_base.js`).

줌 대응 관계는 배포 환경에서 level 1~14를 실측해 확정했습니다.

```
카카오 level L 해상도 = 0.25 × 2^(L-1) m/px      (EPSG:5181, 실제 지상거리)
웹메르카토르 zoom z   = 156543.03392 × cos(위도) / 2^z

  →  z = OFFSET − L,   OFFSET = log2(156543.03392 × cos(위도) / 0.125)
     위도 35.72(달성군)에서 OFFSET = 19.956   (실측 19.936과 일치)
```

OFFSET이 정수가 아니라 Leaflet 줌도 정수가 아닙니다. `zoomSnap:0` 으로 두고 허용 줌을
`{OFFSET−1 … OFFSET−14}` 격자에 스냅시킵니다. 위도에 따라 OFFSET이 미세하게 달라지지만
달성군 전역에서 0.005 미만이라 화면 오차는 1px 미만입니다. 두 지도가 어긋나 보이지 않도록
줌 애니메이션은 꺼 두었습니다.

**지적편집도**(용도지역 색분류)는 우측 하단 `지적` 버튼으로 켭니다. 표준지의 용도지역
기재와 실제 지적편집도를 대조할 때 유용합니다.

## 산정 모델 — 엑셀에서 역산해 검증한 관계식

1,043행 전체에 대해 아래 식이 **100% 일치**함을 확인하고 그대로 구현했습니다
(`js/appraise.js` 상단 주석에 검증 수치 기록).

| # | 관계식 | 일치 |
|---|---|---|
| 1 | `공시지가 = sigRound( (A조 평가액 + B조 평가액) / 2 )` | 685 / 685 |
| 2 | `sigRound(x)` = x ≥ 100,000 → 유효숫자 4자리, 미만 → 3자리 (반올림) | — |
| 3 | `'27 반영률 = round(공시지가 ÷ 시가수준 × 100, 2)` | 1043 / 1043 |
| 4 | `'26 반영률 = round(전년공시지가 ÷ 전년시가수준 × 100, 2)` | 1043 / 1043 |
| 5 | `단순증감률 = round((금년/전년 − 1) × 100, 1)` | 1043 / 1043 |
| 6 | `시가수준변동률 = round((시가수준/전년시가수준 − 1) × 100, 1)` | 1043 / 1043 |
| 7 | `A·B조 격차율 = round((A − B) ÷ A × 100, 2)` | 685 / 685 |

핵심은 **반영률이 입력값이 아니라 결과값**이라는 점입니다.
산정 흐름은 `A·B조 평가액 → 평균·유효숫자 반올림 → 공시지가`이고,
반영률은 그 공시지가를 시가수준으로 나눈 값입니다.
패널의 시뮬레이터는 A조·B조 평가액과 시가수준을 ±15% 범위에서 움직이며
결정 공시지가·반영률·증감률이 어떻게 따라오는지 즉시 보여줍니다.

A조·B조 중 한쪽만 평가한 **단수조**는 358필지이며, 해당 조 가격을 그대로 씁니다.

## 검수(이상치) 기준

임계값은 검수 패널에서 슬라이더로 바로 조정됩니다.

| 코드 | 심각도 | 내용 | 기본 임계값 |
|---|---|---|---|
| `RESID` | ⛔ critical | A·B조 평균 산정액과 공시지가 불일치 | ±0.5% |
| `RATIO` | 🔺 serious | 시가수준 × 반영률 ≠ 공시지가 | ±0.02% |
| `GAP` | 🔺 serious | A·B조 격차율 과다 | ±3% |
| `CHG` | ⚠ warning | 전년 대비 급변 | ±10% |
| `ZDEV` | ⚠ warning | 읍면×이용상황 그룹 내 log 단가 z-score 이탈 | ±2σ |
| `DIR` | ⚠ warning | 시가수준과 공시지가의 변동 방향 불일치 | — |
| `SINGLE` | ⚠ warning | 단수조 — 교차검증 불가 (단독으로는 검수 대상 제외) | — |

균형성(`ZDEV`)은 같은 **읍면 × 이용상황** 그룹의 log 단가 분포와 비교하며,
표본 3건 미만이면 읍면 전체로 넓히고 그래도 부족하면 판정하지 않습니다.

> **현재 데이터 상태 참고** — 지금 들어 있는 표본목록은 `'27 공시지가 = '26 공시지가`,
> `시가수준 = 전년 시가수준` 인 **산정 착수 전 상태**입니다. 따라서 `CHG`·`DIR` 검수는
> 금년 값이 입력되기 전까지 걸리지 않습니다. 현재 걸리는 항목은 `GAP` 2건, `ZDEV` 35건입니다.

## 화면 구성

- **좌측 패널** — 읍·면/이용상황 칩, 지목·용도지역, 소재지·지번·PNU 검색, 지도 색상 기준, 필지 목록
- **지도** — 카카오 배경지도(일반·위성·하이브리드·지적편집도) 위에 원형 마커(색 = 선택한 지표, 크기 = 필지 면적), 확대 시 지가 라벨, 히트맵
- **🧮 산정** — 선택 필지의 산정 6단계(평가액 → 결정가격 → 반영률 → 전년 대비 → 검증 → 인근 비교) + 메모
- **🚩 검수** — 임계값 슬라이더, 점수순 검수 목록, CSV 내보내기
- **📊 통계** — 필지 수/검수 건수/중위 지가/면적가중 평균/증감률/반영률, 로그 분포 히스토그램, 읍·면별 요약

지도 색상은 크기 지표(공시지가·시가수준·반영률)에 **단일 blue 램프 5분위**,
부호 지표(증감률·격차율·산정오차·균형성편차)에 **blue↔red 발산형 + 중립 회색**을 씁니다.
발산형 중립색은 지도 배경 위에서 사라지지 않도록 문서 기본값보다 한 단계 진한 회색(`#cbd5e0`)을 썼습니다.

## 파일 구조

```
index.html                 화면 구조
css/style.css              스타일 · 색상 토큰
js/appraise.js             산정/검증 도메인 로직 (DOM 비의존, 단위 테스트 가능)
js/kakao_base.js           카카오 배경지도 + Leaflet 동기화
js/geocode.js              지오코딩 · 좌표 캐시 · CSV 가져오기/내보내기
js/app.js                  지도 · 필터 · 패널 · 렌더
data/parcels.js            표준지 1,043필지 (자동 생성)
data/coords.js             PNU → 좌표 캐시 (자동 생성, 최초엔 비어 있음)
tools/build_parcels.ps1    표본목록.xls → data/parcels.js 재생성
tools/serve.ps1            의존성 없는 로컬 정적 서버
표본목록.xls               원본 데이터
KakaoTalk_Longtxt_*.txt    참고한 유사 프로젝트(은행 지점 지도) 원문
```

엑셀이 갱신되면:

```bash
powershell -ExecutionPolicy Bypass -File tools/build_parcels.ps1
```

`data/coords.js` 는 PNU 기준이므로 필지 구성이 바뀌지 않는 한 그대로 재사용됩니다.

## 저장되는 값

브라우저 `localStorage` 에 좌표 캐시(`gongsi.coords.v1`)와 현장조사 메모(`gongsi.memo.v1`)가
저장됩니다. 기기·브라우저마다 별도이며 서버로 전송되지 않습니다.
공유가 필요하면 좌표는 `coords.js` 로, 메모는 검수/통계 패널의 **CSV 내보내기**로 넘기세요.

브라우저 콘솔에서 `__gis` 로 데이터와 지도 객체에 바로 접근할 수 있습니다
(예: `__gis.recs.filter(r => r.flagged).length`).
