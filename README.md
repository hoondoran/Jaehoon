# 공시지가 산정 — 표준지 GIS

표본목록 엑셀의 **텍스트 소재지(G열 "표준지 위치")** 를 좌표로 바꿔 지도에 올리고,
표준지 공시지가의 **산정식을 재계산·검증**하는 단일 페이지 웹 도구입니다.

대상: **대구광역시 달성군 표준지 1,043필지** (화원읍 321 · 논공읍 364 · 옥포읍 358)

---

## 빠르게 실행

카카오 지도 SDK는 `file://` 에서 동작하지 않으므로 로컬 서버로 엽니다.
Node·Python 없이 PowerShell만으로 동작합니다.

```bash
powershell -ExecutionPolicy Bypass -File tools/serve.ps1
```

브라우저에서 <http://localhost:8080> 접속. **좌표는 이미 `data/coords.js` 에 들어 있어
(1,043필지 전부) 지오코딩 없이 바로 지도가 뜹니다.**

배포본: <https://hoondoran.github.io/Jaehoon/>

## 좌표 확보 (텍스트 소재지 → GIS)

엑셀에는 좌표 열이 없고 지번주소와 PNU만 있습니다. 두 가지 경로를 지원합니다.

**① 카카오 지오코딩 (기본 · 실행 완료)**
`대구광역시 달성군` + G열 지번주소로 조회하고, 실패하면 도로명주소 → 본번만 순으로
재시도합니다. 결과는 브라우저 `localStorage` 에 캐시되고 `data/coords.js` 로 내보냅니다.

> **1,043필지 전부 변환 완료 (실패 0건).** 전 건이 1순위인 지번주소로 직접 매칭돼
> 도로명·본번 대체 경로는 쓰이지 않았습니다. 중복 좌표 0건, 전 필지가 달성군 경계
> (위도 35.716~35.819 / 경도 128.392~128.547) 안에 들어옵니다.
>
> 엑셀에 필지가 추가됐을 때만 **📍 좌표 변환**을 다시 돌리면 됩니다. 이미 좌표가 있는
> 필지는 건너뛰므로 추가분만 조회합니다. 끝나고 **⬇ coords.js 저장**을 누르면,
> `tools/serve.ps1` 로 띄운 로컬 서버에서는 `data/coords.js` 를 곧바로 덮어쓰고
> (개발 전용 `POST /__save-coords`), 그 외 환경에서는 파일 다운로드로 넘어갑니다.

> **appkey 도메인 등록이 필요합니다.**
> [카카오 개발자 콘솔](https://developers.kakao.com) → 내 애플리케이션 → 플랫폼 → Web 에
> `http://localhost:8080` 과 GitHub Pages 주소(`https://<계정>.github.io`)를 등록하세요.
>
> 등록되지 않은 도메인에서도 **SDK 스크립트 자체는 정상 로드됩니다.** 거부되는 것은
> 주소 검색(`addressSearch`) 호출이고, 이때 카카오는 "결과 없음"이 아니라 오류를 돌려줍니다.
> 그래서 겉보기에는 "변환은 도는데 전부 실패"처럼 보입니다. 이 경우를 구분하려고
> 초반 5회가 모두 거부되면 즉시 중단하고 등록해야 할 origin을 그대로 찍어 줍니다.
>
> appkey는 `index.html` 하단 스크립트 태그에서 바꿉니다.

**② 좌표 CSV 가져오기 (대체)**
카카오 키를 쓸 수 없을 때 **⬆ 좌표 CSV** 로 `PNU, 위도, 경도` 열을 가진 CSV를 넣으면 됩니다.
헤더 이름(`PNU`/`고유번호`, `위도`/`lat`/`y`, `경도`/`lng`/`x`)을 자동 인식하고,
헤더가 없으면 1·2·3열로 봅니다. 위경도가 뒤바뀐 파일도 자동 보정합니다.

## 배경지도 — 카카오맵

배경지도(일반·위성·하이브리드·**지적편집도**)는 카카오맵을 쓰고, 마커 1,000여 개의
캔버스 렌더링과 히트맵은 Leaflet이 담당합니다. `#kakao-map`(아래) 위에 투명한
`#map`(Leaflet)을 겹쳐 두고, 조작은 Leaflet이 받아 카카오 지도를 따라오게 동기화합니다
(`js/kakao_base.js`).

줌 대응 관계는 배포 환경에서 level 1~14를 실측해 확정했습니다.

```
카카오 level L 해상도 = 0.25 × 2^(L-1) m/px      (EPSG:5181, 실제 지상거리)
웹메르카토르 zoom z   = 156543.03392 × cos(위도) / 2^z

  →  z = OFFSET − L,   OFFSET = log2(156543.03392 × cos(위도) / 0.125)
     위도 35.72(달성군)에서 OFFSET = 19.956   (실측 19.936과 일치)
```

OFFSET이 정수가 아니라 Leaflet 줌도 정수가 아닙니다. `zoomSnap:0` 으로 두고 허용 줌을
`{OFFSET−1 … OFFSET−14}` 격자에 스냅시킵니다. 위도에 따라 OFFSET이 미세하게 달라지지만
달성군 전역에서 0.005 미만이라 화면 오차는 1px 미만입니다. 두 지도가 어긋나 보이지 않도록
줌 애니메이션은 꺼 두었습니다.

**지적편집도**(용도지역 색분류)는 우측 하단 `지적` 버튼으로 켭니다. 표준지의 용도지역
기재와 실제 지적편집도를 대조할 때 유용합니다.

## 현장조사 10일 계획 — 동선 배정

1,043필지를 **10일로 나누고 하루 안의 방문 순서까지** 정합니다. 개수만 맞춰 자르면
하루에 군 전역을 돌게 되므로 세 단계로 동선을 줄입니다 (`js/route.js`).

| 단계 | 방법 |
|---|---|
| ① 일차 묶기 | **정원 제약 k-means** — 지리적으로 뭉치되 하루 물량이 고르도록 |
| ② 일차 순서 | 군집 중심 10개를 TSP로 풀어 N일차와 N+1일차가 인접하게 번호 부여 |
| ③ 하루 경로 | 최근접 이웃 + 2-opt 로 방문 순서 결정 (전날 종료지점에서 가까운 곳부터 시작) |

보통의 k-means는 가장 가까운 중심에 무조건 붙여서 하루 151필지 vs 81필지까지 갈렸고,
정원을 지키게 하니 한 군집이 먼저 차버린 탓에 밀려난 점이 생겨 3일차 반경이 10km까지
벌어졌습니다. 그래서 **정원을 유지한 채 두 점을 맞바꾸는 교환 개선**을 덧붙였습니다.

| | 개수 편차 | 최대 반경 | 총 이동(직선) |
|---|---|---|---|
| 기본 k-means | 81 ~ 151 | — | — |
| + 정원 제약 | 104 ~ 105 | 10.0 km | 251 km |
| + 교환 개선 | 104 ~ 105 | **3.5 km** | **233 km** |

결과는 하루 104~105필지, 하루 이동 12~36km입니다. 이동거리는 도로가 아닌 **직선거리**
합계라 실제보다 짧게 잡힙니다. 순서를 정하는 데 쓰는 값으로만 보세요.

**사용법** — 좌측 `현장조사 일차` 칩에서 일차를 고르면 그날 필지만 남고 **방문 순서대로
동선이 그려집니다**(출발 지점 표시). 요약 라벨 머리줄에 `6일차 · 29번`이 찍히고,
`지도 색상 기준`을 `현장조사 일차`로 바꾸면 10일 전체를 한눈에 봅니다.
`⬇ 조사순서 CSV` 는 일차·방문순서대로 정렬해 내보냅니다.

일차는 순서가 있는 값이라 범주형 색이 아니라 **단일 blue 램프 10단계**(연함 → 진함)를
씁니다. 색만으로 1~10일차를 구분하는 건 무리라서 일차는 라벨·목록·범례에 **글자로도**
찍힙니다.

> 좌표가 바뀌면(지오코딩·CSV 가져오기) 자동으로 다시 계산합니다.
> 수동으로 다시 짜려면 `🗺 일차 계획` 버튼을 누르세요.
> 일수를 바꾸려면 `js/app.js` 의 `PLAN_DAYS` 를 고칩니다.

## 모바일 (갤럭시 · 안드로이드)

현장 조사용으로 **통신이 끊겨도 동작**합니다. 로컬 서버를 내린 상태에서 1,043필지·검수
판정·카카오 타일까지 그대로 표시되는 것을 확인했습니다.

### ① 홈 화면 설치 (PWA — 설치 파일 불필요)

갤럭시 크롬으로 <https://hoondoran.github.io/Jaehoon/> 접속 →
메뉴(⋮) → **홈 화면에 추가**. 주소창 없는 전체화면으로 뜨고, 아이콘을 길게 누르면
**검수 / 통계** 바로가기가 나옵니다.

첫 접속 때 앱 셸(HTML·CSS·JS·표준지 데이터 443KB)을 통째로 받아 두고,
이후 둘러본 지도 타일은 최대 900장까지 캐시합니다. 현장 나가기 전에 담당 구역을
한 번 훑어 두면 그 범위는 오프라인에서도 지도가 보입니다.

### ② APK 설치 (앱으로 설치)

이 PC에는 JDK·Android SDK가 없어 **GitHub Actions에서 빌드**합니다. 설치할 것 없습니다.

1. 저장소 **Actions** 탭 → **APK 빌드** → `Run workflow`
   (`android/` 아래를 고치면 자동으로도 돕니다)
2. 실행 결과 페이지 하단 **Artifacts → `gongsi-gis-apk`** 내려받기 (zip)
3. 압축을 풀어 나온 `.apk`를 갤럭시로 옮겨 실행
4. "출처를 알 수 없는 앱" 설치 허용

`v1.0` 같은 태그를 밀면 **Release에 APK가 자동 첨부**됩니다.

```bash
git tag v1.0 && git push origin v1.0
```

> **디버그 서명 APK입니다.** 사내 사이드로드용이고 Play 스토어 배포용이 아닙니다.
> 스토어에 올리려면 릴리스 키스토어를 만들어 저장소 Secret으로 넣고 서명 단계를
> 추가해야 합니다.

`android/` 는 배포된 PWA를 띄우는 **WebView 래퍼**입니다. 앱 안에 웹 파일을 번들하지
않고 원격 URL을 여는 이유는, 카카오 지도 SDK가 **등록된 도메인에서만 동작**하기
때문입니다(`file://` 로 열면 SDK가 거부합니다). 오프라인은 페이지의 서비스워커가
담당하고, 앱은 그 위에서 뒤로가기·위치권한·파일 저장만 처리합니다.

CSV 내보내기는 `Blob` URL을 쓰는데 WebView의 `DownloadListener`가 `blob:` 을 받지
못합니다. 그래서 페이지 안에서 base64로 읽어 JS 브리지로 넘긴 뒤 앱이 파일로 씁니다
(`Android/data/kr.gongsi.gis/files/Download/`).

## 산정 모델 — 엑셀에서 역산해 검증한 관계식

1,043행 전체에 대해 아래 식이 **100% 일치**함을 확인하고 그대로 구현했습니다
(`js/appraise.js` 상단 주석에 검증 수치 기록).

| # | 관계식 | 일치 |
|---|---|---|
| 1 | `공시지가 = sigRound( (A조 평가액 + B조 평가액) / 2 )` | 685 / 685 |
| 2 | `sigRound(x)` = x ≥ 100,000 → 유효숫자 4자리, 미만 → 3자리 (반올림) | — |
| 3 | `'27 반영률 = round(공시지가 ÷ 시가수준 × 100, 2)` | 1043 / 1043 |
| 4 | `'26 반영률 = round(전년공시지가 ÷ 전년시가수준 × 100, 2)` | 1043 / 1043 |
| 5 | `단순증감률 = round((금년/전년 − 1) × 100, 1)` | 1043 / 1043 |
| 6 | `시가수준변동률 = round((시가수준/전년시가수준 − 1) × 100, 1)` | 1043 / 1043 |
| 7 | `A·B조 격차율 = round((A − B) ÷ A × 100, 2)` | 685 / 685 |

핵심은 **반영률이 입력값이 아니라 결과값**이라는 점입니다.
산정 흐름은 `A·B조 평가액 → 평균·유효숫자 반올림 → 공시지가`이고,
반영률은 그 공시지가를 시가수준으로 나눈 값입니다.
패널의 시뮬레이터는 A조·B조 평가액과 시가수준을 ±15% 범위에서 움직이며
결정 공시지가·반영률·증감률이 어떻게 따라오는지 즉시 보여줍니다.

A조·B조 중 한쪽만 평가한 **단수조**는 358필지이며, 해당 조 가격을 그대로 씁니다.

## 검수(이상치) 기준

임계값은 검수 패널에서 슬라이더로 바로 조정됩니다.

| 코드 | 심각도 | 내용 | 기본 임계값 |
|---|---|---|---|
| `RESID` | ⛔ critical | A·B조 평균 산정액과 공시지가 불일치 | ±0.5% |
| `RATIO` | 🔺 serious | 시가수준 × 반영률 ≠ 공시지가 | ±0.02% |
| `GAP` | 🔺 serious | A·B조 격차율 과다 | ±3% |
| `CHG` | ⚠ warning | 전년 대비 급변 | ±10% |
| `ZDEV` | ⚠ warning | 읍면×이용상황 그룹 내 log 단가 z-score 이탈 | ±2σ |
| `DIR` | ⚠ warning | 시가수준과 공시지가의 변동 방향 불일치 | — |
| `SINGLE` | ⚠ warning | 단수조 — 교차검증 불가 (단독으로는 검수 대상 제외) | — |

균형성(`ZDEV`)은 같은 **읍면 × 이용상황** 그룹의 log 단가 분포와 비교하며,
표본 3건 미만이면 읍면 전체로 넓히고 그래도 부족하면 판정하지 않습니다.

> **현재 데이터 상태 참고** — 지금 들어 있는 표본목록은 `'27 공시지가 = '26 공시지가`,
> `시가수준 = 전년 시가수준` 인 **산정 착수 전 상태**입니다. 따라서 `CHG`·`DIR` 검수는
> 금년 값이 입력되기 전까지 걸리지 않습니다. 현재 걸리는 항목은 `GAP` 2건, `ZDEV` 35건입니다.

## 화면 구성

- **좌측 패널** — 읍·면/이용상황 칩, 지목·용도지역, 소재지·지번·PNU 검색, 지도 색상 기준, 필지 목록
- **지도** — 카카오 배경지도(일반·위성·하이브리드·지적편집도) 위에 원형 마커, 요약 라벨, 히트맵
- **🧮 산정** — 선택 필지의 산정 6단계(평가액 → 결정가격 → 반영률 → 전년 대비 → 검증 → 인근 비교) + 메모
- **🚩 검수** — 임계값 슬라이더, 점수순 검수 목록, CSV 내보내기
- **📊 통계** — 필지 수/검수 건수/중위 지가/면적가중 평균/증감률/반영률, 로그 분포 히스토그램, 읍·면별 요약

### 마커 · 요약 라벨 · 필지 외곽선

**마커 크기는 모두 같습니다.** 면적을 크기로 나타내면 색(선택한 지표)과 크기를 동시에
읽어야 해서, 크기는 아무 값도 encoding 하지 않습니다. 면적은 라벨·산정 패널의 숫자로 봅니다.

**요약 라벨**에는 소재지 / 단가 / 용도지역 · 이용상황이 한 장에 담기고, 검수 대상은 우측 상단에
아이콘이 붙습니다. **라벨을 클릭하면 산정 패널에 세부 정보**가 열립니다.
1,043개를 전부 띄우면 읽을 수 없으므로 화면 좌표에서 겹치는 것은 버리고,
`선택 필지 → 검수 대상 → 지가 높은 순`으로 자리를 줍니다. 확대할수록 더 많이 보입니다
(군 전체 8개 → 읍 단위 31개 수준).

**필지 외곽선**은 `data/shapes.js` 의 `PARCEL_SHAPES`(PNU → 폴리곤 링)가 채워지면
`kakao.maps.Polygon` 으로 그려집니다. 선택 필지는 항상, 그 외에는 충분히 확대했을 때
화면 안 필지까지 함께 표시하고 클릭하면 동일하게 세부 정보가 열립니다.

> **카카오 API는 필지 경계 좌표를 제공하지 않습니다.** SDK에 `Polygon`(그리기)은 있지만
> `kakao.maps.services` 에는 `Geocoder` 와 `Places` 뿐이고 지적 데이터 API가 없습니다
> (`USE_DISTRICT` 지적편집도는 벡터가 아닌 래스터 오버레이입니다).
> 경계 좌표는 **VWorld 데이터 API**(`LP_PA_CBND_BUBUN` 연속지적도, 무료·키 필요) 또는
> 국가공간정보포털 연속지적도 SHP 에서 받아 `data/shapes.js` 에 넣어야 합니다.
> 비어 있으면 외곽선만 생략되고 나머지 기능은 그대로 동작합니다.

지도 색상은 크기 지표(공시지가·시가수준·반영률)에 **단일 blue 램프 5분위**,
부호 지표(증감률·격차율·산정오차·균형성편차)에 **blue↔red 발산형 + 중립 회색**을 씁니다.
발산형 중립색은 지도 배경 위에서 사라지지 않도록 문서 기본값보다 한 단계 진한 회색(`#cbd5e0`)을 썼습니다.

## 저장되는 값

브라우저 `localStorage` 에 좌표 캐시(`gongsi.coords.v1`)와 현장조사 메모(`gongsi.memo.v1`)가
저장됩니다. 기기·브라우저마다 별도이며 서버로 전송되지 않습니다.
공유가 필요하면 좌표는 `coords.js` 로, 메모는 검수/통계 패널의 **CSV 내보내기**로 넘기세요.

브라우저 콘솔에서 `__gis` 로 데이터와 지도 객체에 바로 접근할 수 있습니다
(예: `__gis.recs.filter(r => r.flagged).length`).
